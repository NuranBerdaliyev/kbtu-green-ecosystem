Да — теперь проект можно показать как целостный управляемый MVP. Но «поднять на пустой БД и сразу демонстрировать без подготовки» пока нельзя.

Я проверял именно обновлённый фронт:

* восстановил его из присланного контекста;
* `npm ci` проходит;
* production-сборка Vite проходит;
* ESLint проходит без ошибок;
* основные запросы фронта совпадают с текущими backend-контроллерами и DTO.

### Единственный обязательный bootstrap

На пустой БД первый пользователь всегда создаётся как `STUDENT`. Dev-seed или создание первого ADMIN в присланном backend-коде я не нашёл. Поэтому первоначальную административную учётку нужно один раз повысить через SQL:

```bash
docker exec -it kbtu_green_db psql \
  -U green_user \
  -d kbtu_green_ecosystem \
  -c "UPDATE users SET role = 'ADMIN' WHERE email = 'admin@demo.kz';"
```

До этого `admin@demo.kz` нужно зарегистрировать через фронт. После SQL — выйти и войти заново, чтобы фронт получил новую роль в JWT. Остальные роли дальше назначаются через «Админ → Пользователи».

То есть галочка «создание первого ADMIN» фактически закрыта только ручным bootstrap, не автоматически.

### Лучший сценарий демонстрации

Подготовить четыре аккаунта:

* ADMIN;
* HR;
* студент-водитель;
* студент-пассажир.

Дальше показать следующую цепочку.

1. ADMIN создаёт пластиковый контейнер:

    * вместимость: `5000 г`;
    * активен;
    * уникальный QR-токен.

2. Студент сдаёт `4500 г`.

   На фронте появляется честный статус «Ожидает подтверждения». Баланс и контейнер пока не меняются.

3. ADMIN подтверждает заявку.

   После этого одновременно:

    * контейнер становится заполнен на 90%;
    * студент получает 45 EcoCoins;
    * увеличиваются ESG и CO₂;
    * появляется запись в истории;
    * открываются первые достижения;
    * карта контейнеров обновляется через WebSocket;
    * ADMIN получает alert о пересечении 90%.

   Для показа alert админ-панель должна быть открыта в отдельной вкладке в момент подтверждения — события не сохраняются как уведомления.

4. Водитель создаёт поездку рядом с кампусом:

    * цена, например, `5 EcoCoins`;
    * время отправления через 1–2 минуты;
    * затем нажимает «Опубликовать».

5. Пассажир присоединяется.

   Его баланс уменьшается на 5 EcoCoins, а оплата получает статус `RESERVED`.

6. После наступления времени водитель нажимает:

    * «Начать поездку»;
    * «Завершить».

   Результат:

    * водитель получает 5 EcoCoins;
    * оплата пассажира становится завершённой;
    * водитель и пассажир получают ESG и CO₂;
    * профиль, история и лидерборд показывают результат.

7. HR создаёт компанию.

8. ADMIN подтверждает ей статус партнёра.

9. HR создаёт вакансию.

10. Студент откликается, а HR открывает кандидатов и видит его экологические показатели.

Так получается именно история из README:

```text
Экологическое действие
→ EcoCoins и ESG
→ история и лидерборд
→ ESG-профиль виден работодателю
```

### Что нужно учесть перед показом

* Backend требует Java 21 и системный Maven: `mvnw` в присланном проекте отсутствует.
* `docker-compose.yml` запускает только PostgreSQL/PostGIS, не весь проект.
* Backend работает на `65535`, frontend на `5173`; Vite proxy настроен правильно.
* Для одновременного ADMIN и STUDENT лучше использовать обычное и приватное окно браузера.
* Чтобы показать отметку «Рекомендован», нужен ESG ≥ 70. Для короткой демонстрации можно временно поставить `recommended-esg-threshold: 3`; иначе HR всё равно увидит ESG, EcoCoins и CO₂, но без специального бейджа.

Итог: для презентации MVP — да, готово. Главные прежние рассинхронизации фронта с backend исправлены. Перед выступлением обязательно нужен один полный прогон на реальном PostgreSQL, поскольку здесь я смог подтвердить сборку фронта и соответствие контрактов, но не запустить полноценный backend E2E: в среде нет Maven/Java 21 и самой рабочей БД.
